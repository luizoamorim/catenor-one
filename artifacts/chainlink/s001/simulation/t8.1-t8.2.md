### Key observations

1. **Base64 transport SIMULATION-CONFIRMED.** The T0.7 spike carried nonce and ciphertext as hex. This run uses base64 strings (`nonce.toString('base64')`, `ctWithTag.toString('base64')` on the sealing side; pure-JS `base64Decode` on the TEE side — no `atob`/`btoa`). The context opened successfully in the CRE QuickJS/WASM runtime.

2. **Pure-JS base64 works in QuickJS.** The implementation in `shared/base64.ts` uses only `Uint8Array`, `charCodeAt`, `parseInt` — no Node or browser globals.

3. **All 6 tamper/mismatch cases fail closed.** Wrong key, AAD mismatch, runId mismatch, bit-flipped ciphertext, bit-flipped tag, and expired context all produce `SEALED_CONTEXT_OPEN_FAILED` with zero HTTP calls.

4. **Unknown operation returns UNKNOWN_OPERATION with zero HTTP calls.** The unknown-operation payload was sealed correctly for `UNKNOWN_OPERATION` (so the context opens), but the router rejects it — confirming that context-open success does not imply authorization.

5. **Synchronous handler invocation.** The CRE TEE handler is synchronous (`(runtime, triggerOutput) => string`). The TTA handler interface was changed from `async` to sync because QuickJS defers `.then()` callbacks. All CRE SDK calls (`.result()`) resolve synchronously. This is a reference-implementation detail; the real handler may use internal async patterns as long as all I/O is through synchronous CRE SDK calls.

6. **Non-determinism warnings.** The compiler flagged `Object.entries()` ordering in `multiHeaders` construction — mitigated with `.sort()`.

## Deviations from task

1. **`cre init` created a sub-directory** (`workflows/catenor-one/`) instead of using `workflows/` as the project root. Files were moved up manually. Reported as instructed.

2. **TTA handler interface changed from `async` to sync.** The CRE TEE handler is inherently synchronous. QuickJS defers `.then()` callbacks, so the async-to-sync bridge pattern (`promise.then(r => result = r)`) does not work. The stub's return type is `TtaResult` (not `Promise<TtaResult>`). The main session should use the sync form or convert to async only if QuickJS's `await` semantics are validated separately.

3. **Simulation env file path.** `cre workflow simulate -e .env.simulation-synthetic` reads the env file from the project root (`workflows/`). The maintainer will later use `cre workflow simulate -e .env` for the real `.env` with Sumsub sandbox credentials. The `-e` flag accepts a relative path from the CRE project root.

4. **`--trigger-index 0` required** for `--non-interactive` mode (not mentioned in PLAN but documented in CLI help).
