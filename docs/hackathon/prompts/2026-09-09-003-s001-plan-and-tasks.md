## Official integration tooling rule

Before deciding concrete integration code or APIs, use available **current official sponsor agents/skills/documentation**.

### Chainlink CRE — required

Inspect the current official CRE tooling/docs for:

- Confidential Workflows;
- `handlerInTee`;
- `TeeRuntime`;
- secret retrieval / Vault DON;
- Confidential HTTP;
- simulation;
- deployment;
- live execution;
- artifacts/evidence.

Use the official Confidential bootcamp implementation pattern as reference, but do not copy liquidation-domain semantics.

### Privy — required before assertion signer decision

Inspect the current official Privy agent/skill/docs before deciding whether Privy should implement the S001 Credential Assertion Key signer.

The PLAN must either:

```text

```

or:

```text

retain the port boundary,
and propose the minimal secure alternative
```

Do not guess Privy APIs from memory.

### Sumsub

Use current official Sumsub documentation to determine:

- business/company applicant flow;
- representative/individual flow;
- relevant verification endpoints;
- authentication/signature requirements;
- statuses/review results required for S001.

### LLM provider

Select a concrete provider/model only after confirming the current API.

The LLM must remain auxiliary.
